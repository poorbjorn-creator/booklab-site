# GROK-RULES.md — Rules for the `grok/updates` Branch

**You are a contributor, not a deployer.** You commit to `grok/updates`. Alfred reviews, merges to `main`, builds, and deploys. You never deploy.

## Scope

### Allowed
- Edit **existing** pages in `_src/` only
- Fix typos, improve wording, clarify sentences
- Add internal crosslinks between existing pages
- Update meta descriptions, OG tags, structured data
- Optimize or replace existing images (same path, same format)
- Fix broken links or outdated references
- Add missing `alt` text

### NOT Allowed
- Create new pages or new files
- Delete pages or files
- Edit anything outside `_src/` (no build scripts, deploy scripts, config, templates, `_includes/`, root HTML)
- Change page structure, layout, or styling (CSS)
- Add external scripts or dependencies
- Modify `build.py`, `deploy.sh`, `_redirects`, `CONTRIBUTING.md`, or this file
- Touch `sitemap.xml` (Alfred handles sitemap updates on merge)
- Add or change Amazon affiliate links
- Deploy to production

## Commit Prefixes

Every commit message **must** start with one of these prefixes:

| Prefix   | Use for |
|----------|---------|
| `fix:`   | Typos, grammar, factual corrections |
| `link:`  | Adding or fixing internal crosslinks |
| `meta:`  | OG tags, meta descriptions, structured data, alt text |
| `image:` | Image optimization, replacement (same path) |
| `copy:`  | Rewriting or improving existing text |

**Format:** `prefix: short description of what changed`

**Examples:**
- `fix: typo in flow review - "psycology" → "psychology"`
- `link: add crosslink from sapiens review to spiral dynamics`
- `meta: update OG description for great books list`
- `copy: tighten intro paragraph on denial of death review`

## Rules

1. **Only edit `_src/` files.** The built output files are generated by `build.py` — never touch them directly.
2. **One logical change per commit.** Don't bundle unrelated fixes.
3. **Match existing style.** Don't reformat code, change indentation patterns, or "improve" adjacent HTML.
4. **Preserve the author's voice.** Bjorn's writing has a specific tone. Fix errors, don't rewrite personality.
5. **No em dashes (—).** Use regular dashes (-) or rewrite the sentence.
6. **All internal links must be root-relative** (start with `/`). Never use relative paths.
7. **All internal links must be extensionless.** `/reviews/flow-mihaly-csikszentmihalyi` not `.html`.
8. **Only link to pages that exist.** Check `_src/` before adding a crosslink.
9. **Amazon links use `?tag=poorbjorn-20`** (or `&tag=poorbjorn-20` if params exist). Don't change existing affiliate links.
10. **Don't add Amazon links inline in body text.** Amazon links belong in buttons only. Inline links = internal site links only.

## Review Process

When Alfred merges your branch, he checks:
- [ ] Only `_src/` files were changed
- [ ] All commit prefixes are valid
- [ ] Changes follow CONTRIBUTING.md rules
- [ ] No broken internal links
- [ ] No style/structure changes
- [ ] Author's voice preserved
- [ ] Build passes clean

If something fails review, Alfred will note what needs fixing and skip those commits.

## Questions?

Ask Bjorn or Alfred. When in doubt, don't commit — flag it instead.
